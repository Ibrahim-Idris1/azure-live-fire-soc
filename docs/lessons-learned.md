# Lessons Learned

- **APT lock collisions during provisioning:** `unattended-upgrades` can hold `/var/lib/apt/lists/lock` while the provisioning script starts its own `apt-get` operations. Provisioning now waits for that lock to clear before proceeding.
- **Auditd rules file newline handling:** Appending rules without guarding against a missing trailing newline can concatenate directives and corrupt the auditd rules file. The correction was to rewrite the managed rules file idempotently with `tee` instead of appending.
- **Alert volume, duplicates, and analyst fatigue:** Initial triage of roughly 700 Sentinel alerts found four incidents that produced useful investigation findings; many of the remaining alerts appeared to be duplicates or repeated alerts for the same activity. Treat this as a preliminary triage result until incidents are deduplicated and counted consistently. The SSH brute-force rule generated especially high volume. Before the next event, review its alert grouping and suppression behavior so repeated five-minute matches for the same source and host do not overwhelm analysts, while preserving visibility of new sources, hosts, and activity. Validate any tuning against representative attack and benign data before deployment.
