# Reports

This folder stores the project report artifacts, metrics, and after-action documentation.

## Purpose

At the end of the live-fire exercise, the team should produce a concise but professional report showing:

- what was built,
- what was attacked,
- what was detected,
- what was missed,
- what was improved after the event.

## Typical Included Documents

- after-action report
- detection coverage summary
- top attacker behaviors observed
- timeline dashboard screenshots or exports
- lessons learned
- improvements for the next iteration

## Reporting Standard

Each report should include:

- event scope,
- date range,
- environment overview,
- attack summary,
- detections fired,
- false positives or gaps,
- recommendations.

## Reporting Goal

The final report should read like a real incident review, not a classroom exercise. It should show both what worked and what failed, because the real value of the project is in the lessons learned and improved detection coverage.
